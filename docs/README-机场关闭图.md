# 机场关闭图生成器 · 使用说明

输入一个 ICAO 代码（KJFK / KLAX / PANC…），自动读出该机场的关闭通告，把被关闭的**跑道**和**滑行道分段**标注到机场图上，输出一张 PNG。

---

## 一、两种运行方式

### 方式 A：网页版（推荐，免安装）

1. 解压后双击 **`启动-网页版.bat`**
2. 浏览器会自动打开 `http://127.0.0.1:8765`
3. 在页面输入 ICAO → 点“生成标注图”
4. 用完关掉黑色窗口即可

前提：电脑装了 Python 3.9+（安装时勾选 *Add Python to PATH*）。bat 会自动补装依赖。

### 方式 B：打包成单文件 exe

双击 **`打包exe.bat`**，等 2–4 分钟，产物在 `dist\机场关闭图.exe`，之后双击 exe 即可（同样会自动开网页）。

> 打包本身必须在 Windows 上做：PyInstaller 不支持跨平台交叉编译。我这边是 Linux 构建机，只能验证打包参数正确、不能产出 .exe。

---

## 二、页面怎么用

| 项 | 说明 |
|---|---|
| 机场 ICAO | 4 位代码，如 KJFK、KLAX、PANC、KORD |
| 目标时间（UTC） | 填航班的**预计到达时间 ETA**，UTC，如 `2026-11-19 14:00`。填了就只保留与该时间**前后 6 小时**有交集的通告；留空则不限时间 |
| HTTP 代理（可选） | 如 `http://127.0.0.1:7890`。抓不到通告时用这个 |
| 粘贴通告文本 | 每条形如 `11/292 TWY Y BTN TWY G AND TWY H CLSD 11/19/2026 1215 11/19/2026 2300` |

页面会给出：
- 标注图（点图可放大）
- 已上图清单：编号 / 要素 / 通告号 / 起止 / 长期还是短时
- **未上图清单**：要素在图上找不到时如实列出原因，不硬标

## 三、关于 403（已解决，2026-11-20 更新）

早先版本抓通告会返回 **403 Access Denied**。根因已查明：**不是 IP 被封锁**，是 FAA 前置的 Akamai 按
**TLS 指纹（JA3）** 判定自动化客户端——Python `requests` 用的是 OpenSSL 默认握手指纹，特征太明显，
所以哪怕 UA、Referer、Cookie 全对也一律 403。真实浏览器访问同一个接口是正常的。

**解决办法**：改用 `curl_cffi`，它把 TLS 握手伪装成 Chrome，同一台机器、同一个 IP 立刻返回 200。
程序里已内置：装了 `curl_cffi` 就自动走它，没装则回退普通 requests。

所以现在国内家宽**不需要代理**也能直接抓。如果你那边还报 403，按下面顺序排查：

1. 确认依赖装上：命令行执行 `pip install curl_cffi`，看到 Successfully installed 即可
2. 公司网络如果有 SSL 解密代理（会重签证书），会破坏 TLS 指纹，这种只能走「粘贴通告」模式
3. 只剩下这两种可能，IP 本身不是问题

下面是原来的兜底办法，仍然保留：

FAA 的 `notams.aim.faa.gov` 在网络异常时会返回 **403**。

三种办法，按顺序试：

1. **填代理**：页面右上“HTTP 代理”，填本机代理地址（Clash/V2Ray 常见 `http://127.0.0.1:7890`）
2. **粘贴模式**：把通告文本贴进文本框（从 FAA 网页、签派系统、SITA 报文里复制都行）
3. **机场官网**：部分美国机场官网会列出当日 NOTAM

只要拿到通告文本，后面的解析和出图完全不受影响。

## 四、出图口径（先说清楚，避免误读）

- **红色实线** = 滑行道关闭段，按通告的 `BTN X AND Y` 截取到具体区段
- **红色斜线** = 整条跑道关闭
- **黄色条** = 通告里提到的要素，在图上/滑行网络里查不到，**不猜位置**
- 时间一律用 **UTC**（FAA 通告的起止本来就是 UTC，程序只做格式化，不做时区换算）
- 同日只写一次日期：`11-20 04:00Z–11:00Z`；跨度超过 3 天的显示完整起止日期
- 每个编号下面那行灰色小字是**通告原文**（E) 段原句），可直接核对，不用回查通告
- 跨度超过 3 天的显示完整起止日期（长期关闭容易被误读成“今天也关”）

**免责**：底图为 X-Plane 场景库的滑行网络 + OurAirports 跑道坐标，属示意图，非官方航图，不得用于运行决策。

## 四之一、落段的三级来源（2026-11-20 更新）

通告只说“R 滑行道在 H 和 G 之间关闭”，要往图上落段，程序按三级依次尝试：

| 级别 | 数据源 | 画出来的样子 | 覆盖 |
|---|---|---|---|
| L1 | X-Plane 滑行网络（apt.dat 线段） | 红色粗线，精确到节点区间 | 常见滑行道，如 H、Y、Q4 |
| L2 | **FAA AM 滑行道面**（官方 Airport Mapping 数据，公开 REST，免密钥） | 红色填充面片 | 含编号分支道 A4、A12、A14、A15、KD 这类网络里没有的要素 |
| L3 | 都没有 | 黄色条进“未上图”，不猜位置 | 极少 |

AM 面片还解决了一个老问题：“B 在 A14 和 A15 之间”这种区间通告，原来因为 A14 不存在只能放弃，现在用两个边界锚点做投影，把 B 上落在区间内的所有面片一起取出来，画成连续的一段。实测 KJFK 的 A4 和 B（A14–A15）已能正常上图，未上图从 3 条降到 0。

实测覆盖：KJFK 452 片、KORD 741 片、KLAX 384 片、PANC 146 片。首次查询会缓存到 `cache\<ICAO>.am_taxiway.json`。

## 四之二、编号不压图

红色编号圈会自动避让：先把所有滑行道字母、跑道端号的占位区登记下来，编号在 16 个方向 × 5 个半径里找第一个不冲突的位置，找不到才退回原地并拉一条细引线。所以像 KJFK 中部 H、G、Z 那种密集区，编号不会盖住字母。

## 五、数据从哪来

| 数据 | 来源 | 缓存位置 |
|---|---|---|
| 通告 | FAA NOTAM Search（免密钥） | 不缓存 |
| 滑行网络 | X-Plane Scenery Gateway 的 apt.dat | `cache\<ICAO>.apt.dat` |
| 跑道坐标 | OurAirports runways.csv（已内置） | 随程序 |

首次查某个机场会下载 0.3–1 MB 的场景包，之后直接读缓存。

## 六、已知上限

- 通告里的分支编号（如 `A4`、`A14`、`A15`）在 FAA 官方图和 X-Plane 网络里都**不标注**，这类会进“未上图”，需要 NASR 命名表才能补
- 机坪（`TERMINAL 8 RAMP`）没有面数据，按“滑行道伸出机坪的末端”截取，位置可信但机坪侧边界是推定的
- 只处理 `CLSD`；`U/S`（灯号/设备不可用）、`WIP`、`CRANE` 不在本图范围
