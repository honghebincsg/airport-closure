# 机场关闭图工具 · 数据源与加工标注逻辑说明

版本：2026-11-20 ｜ 对应程序 `airport_closure_app.py` ｜ 样例机场 KJFK

---

## 一、总览：数据分四层

工具本身不产生任何航空数据，全部是"取公开数据 + 自己算几何 + 自己画"。四层职责要分清，出问题时才定位得快：

| 层 | 作用 | 来源 | 是否必需 |
|---|---|---|---|
| ① 通告层 | 知道"什么关了、关在哪两个要素之间、什么时间段" | FAA NOTAM Search | 必需 |
| ② 网络层 | 知道滑行道/机坪的网络拓扑，用来截出"哪一段" | X-Plane Scenery Gateway `apt.dat` | 必需 |
| ③ 面层 | 网络里没有编号分支道（A4/A14/A15）时，用面片补位 | FAA Airport Mapping `AM_Taxiway` | 可选兜底 |
| ④ 参考层 | 跑道真实端点与宽度；官方航图做对照核验 | OurAirports `runways.csv`；FAA d-TPP AD | 跑道必需 / 航图仅核验 |

## 二、数据源清单

### 1. 通告：FAA NOTAM Search（美国官方，免密钥）

```
POST https://notams.aim.faa.gov/notamSearch/search
Content-Type: application/x-www-form-urlencoded

searchType=0&designatorsForLocation=KJFK&offset=0&limit=50
```

- **协议**：公开页面背后的 AJAX 接口，不需要账号、不需要 API Key。
- **分页**：`offset` 递增、`limit=50`，循环到 `totalNotamCount` 取满（KJFK 当日 181 条）。
- **关键字段**：`notamNumber`（如 `11/295`）、`startDate`、`endDate`（`MM/DD/YYYY HHMM` 本地格式）、`icaoMessage`、`plainLanguageMessage`、`traditionalMessage`、`totalNotamCount`。
- **最重要的一条坑**：**必须用 `curl_cffi` 伪装浏览器 TLS 指纹**。FAA 前置是 Akamai，按 JA3/JA2 指纹判机器人，不是按 IP 封。实测同一台机器同一 IP：`requests` → 403；`curl_cffi(impersonate="chrome")` → 200，返回 214 KB。换 UA、加 Referer、带 Cookie 全部无效。装了 `curl_cffi` 自动走它，没装回退 `requests` 然后 403——这就是很多人"换电脑也 403"的真实原因。
- **正文位置**：`icaoMessage` 常返回整段报文（`Q)… B)… C)… E)…`），必须用正则取 `E)` 之后的部分，否则解析率大幅下降。尾部还会有 `CLSDTWY ZRSTRCTN>…` 这种粘连串，要截断。

### 2. 滑行网络：X-Plane Scenery Gateway（`apt.dat`）

两步换一次文件：

```
① https://gateway.x-plane.com/apiv1/airport/KJFK      → JSON，取 airport.recommendedSceneryId（KJFK=106313）
② https://gateway.x-plane.com/scenery/download/106313 → zip，里面找 *.apt.dat（KJFK 387 KB）
```

- **为什么用它**：`apt.dat` 是 X-Plane 的机场地景规范文本格式，**带完整滑行道网络拓扑**（节点 + 边 + 命名），这是全世界唯一免费、公开、能拿到"哪条边属于哪条滑行道"的数据。OSM 有几何但拓扑和命名不可靠；NASR 只有名字没有几何。
- **解析规则**（`load_network`）：
  - `1201` 行 → 节点：`f[1]`=纬度、`f[2]`=经度、`f[4]`=节点 ID。KJFK 1024 个节点。
  - `1202` 行 → 边：`f[1]`/`f[2]`=两个节点 ID，`f[5:]` 拼接即该段所属滑行道名（`A`、`B`、`Q4`、`TB`、`VA`、`AA`、`C1`…以及跑道穿越段）。KJFK 731 条边。
- **已知局限**：`apt.dat` 的 `100` 行跑道定义经常不全（**KJFK 只给 2 条**），所以跑道几何绝不能用它。
- 中国/非美机场同样可用（如 MMSM 有 200 条边），只是没有 AM 面片兜底。

### 3. 面层：FAA Airport Mapping（AM）—— 你问的 "AOM" 就是这个

先正名：航空数据里没有 "AOM 数据集" 这个通用说法。你可能指的是下面两个之一：

- **AM（Airport Mapping）** —— 就是本工具用的这个。FAA 把机场地面活动区做成矢量要素类，包含 `AM_Taxiway`、`AM_Runway`、`AM_Apron`、`AM_HoldingPosition` 等图层，按 AMDB（Airport Mapping Database）思路生产，坐标是真实经纬度。**工具里用的是 `AM_Taxiway`。**
- **AOM（Airport Operating Manual，机场运行手册）** —— 是机场自己出的运行文件（PDF/纸质），讲机位分配、低能见运行、车辆规则，**不是地理数据源**，本工具不涉及。

`AM_Taxiway` 的具体接口（免密钥，公开 ArcGIS REST）：

```
GET https://services6.arcgis.com/ssFJjBXIUyZDrSYZ/arcgis/rest/services/AM_Taxiway/FeatureServer/0/query
    ?where=ICAO_ID='KJFK'
    &outFields=DESIGNATOR
    &returnGeometry=true
    &outSR=4326
    &geometryPrecision=6
    &f=geojson
```

- **返回**：GeoJSON FeatureCollection，每片是一个 `Polygon`，`properties.DESIGNATOR` 是滑行道名——**关键点：它把编号分支也命名了**，KJFK 有 `A4`、`A12`、`A14`、`A15`、`KD`，还有 `B_A15` 这种"两条道的交叉片"。这正是 `apt.dat` 和官方 AD 图都缺的东西。
- **KJFK 实测**：452 片 / 230 个标识。
- **覆盖范围**：数据集共 **221 个机场**——美国本土 202、阿拉斯加 15、夏威夷 2、波多黎各 1、BAZ 1。**非美机场 0**（MMSM、MMUN、EGLL、ZSPD、RJTT 查询均返回空）。清单在 `docs/FAA_AM滑行道面_覆盖机场清单.csv`。
- **坐标坑**：GeoJSON 是 `[lon, lat]`，程序内部 `xy(lat, lon)`，转换时极易写反，`solve()` 里那行 `xy(pt[1], pt[0])` 就是干这个的。

### 4. 跑道：OurAirports `runways.csv`

```
https://raw.githubusercontent.com/davidmegginson/ourairports-data/main/runways.csv
```

- 全量约 3.8 MB，按 `airport_ident` 过滤目标机场。
- 用到的字段：`le_ident`/`he_ident`（跑道端号）、`le_latitude_deg`/`le_longitude_deg`、`he_latitude_deg`/`he_longitude_deg`（两端真实坐标）、`width_ft`（宽度，英尺，转米时 ×0.3048）。
- **为什么必须有它**：`apt.dat` 的跑道只有 2 条（见上），官方 AD 图是 PDF 不好直接算，OurAirports 是唯一"免费 + 带真实端点坐标 + 带宽度"的表。

### 5. 官方航图底图：FAA d-TPP Airport Diagram（AD）

```
https://aeronav.faa.gov/d-tpp/<cycle>/00610AD.PDF      # KJFK，cycle 实测 2611 可用，305 KB
```

- **这是什么**：FAA 每 28 天一个航图周期（cycle，四位数字，如 `2611`），d-TPP 是官方数字终端程序出版物。`00610AD` 是 KJFK 的 Airport Diagram（机场图）图号，别的机场图号不同（如 KLAX 是 `00282AD`）。
- **是矢量 PDF**：跑道、滑行道、停止排、跑道端号都是矢量对象，可以 `pdfplumber` 直接抽出曲线坐标，也能用 `pdftocairo -r 300` 栅格化成 300 dpi PNG 当底图。
- **当前状态：只用它做人工核验，没有作为主工具底图。** 原因：
  1. AD 图是**示意图纸**，有自己的比例与旋转（图内不严格正北），要把它和经纬度对齐必须做相似变换配准；
  2. 每张图的比例尺、图幅、旋转都不同，一个机场一套标定参数，无法批量；
  3. 配准误差会直接叠到关闭段的定位上，反而降低准确性。
  
  实验脚本是 `make_official_chart.py`（做法：抽 PDF 黑填充长条多边形当跑道 → 与 OurAirports 真实端点配对做 scale+rotation+translation → 把 X-Plane 算出的关闭段反算回 PDF 坐标 → 叠加）。**它未收敛，别当成品用。**

## 三、加工链：从一条通告到一段红线

整条链是**确定性**的（同样输入必得同样输出），没有 AI 参与几何与渲染；语义解析里 AI 只做"文本 → JSON"，并与正则结果交叉核对（规则：正则命中而 AI 未命中 → 以正则为准；AI 命中而正则未命中 → 复核；两边都未命中但原文含 `CLSD` → 报警）。

### 步骤 1｜取通告

分页全量拉取 → 逐条取 `E)` 之后的正文 + 编号 + 起止时间。失败分支：403 直接抛出可操作提示（装 `curl_cffi` / 填代理 / 改用粘贴模式）。

### 步骤 2｜文本 → 关闭对象（`parse_closures`）

按顺序做四件事：

1. **截尾**（`clean`）：去掉 `RSTRCTN>` 之后的粘连串、`>` 残留、尾部时间段 `MM/DD/YYYY HHMM`、`EST/EDT`、`CLSD` 之后的一切杂字。
2. **只要含 `CLSD`/`CLOSED` 的通告**，再按 `,` `;` 拆并列片段。
3. **并列继承**：一条通告里常写 `TWY B BTN A14 AND A15, TWY M BTN R13R/31L AND TWY A CLSD`——`CLSD` 只出现在最后一个片段。规则是：当前片段没有 `CLSD`，但形如 `TWY X BTN …` 且**后面还有片段带 `CLSD`**，则继承关闭含义。
4. **边界对解析**：用 `PAIR` 正则把 `BTN <要素> AND <要素>` 拆成 `b1/b2`，要素允许带 `TWY`/`RWY`/`TERMINAL`/`RAMP`/`APRON` 前缀，允许 `13R/31L`、`RAMP-A` 这类写法。

输出对象：`{编号, 类型(TWY/RWY), 名称, 边界1, 边界2, 前缀类型, 起, 止, 是否继承, 命中证据, 原文}`。KJFK 当日 181 条 → 15 个关闭对象。

### 步骤 3｜取网络与跑道

`apt.dat` 有缓存（`cache/<ICAO>.apt.dat`）就直接用，否则走两步接口下载。跑道走 `runways.csv`。

### 步骤 4｜落段 L1：滑行网络精确截段（`solve`）

以 `TWY X` 为名，取所有 `name == X` 的边构成子图 `sub`，再定两个端点：

- **边界节点集合** `bnodes(twy, bnd)`：先取"该滑行道节点集 ∩ 边界要素节点集"（**共节点**是最可靠的情形）；若无交集，则退化为**距离兜底**——计算边界要素每条线段，取该滑行道节点中距边界线 ≤ **150 m** 的节点。
- **两端句柄**：分别在两侧边界节点集里各取一个，用 `networkx.shortest_path` 在子图上求最短路径，路径上的节点序列就是被关闭的那一段。
- **三种特殊形态**：
  - 只有名称、无 `BTN` → 取该滑行道**最大连通分量**的两个度为 1 的端点，整条关闭。
  - 边界含 `TERMINAL/RAMP/APRON`（机坪侧）→ 以"另一侧边界节点"为起点，找该滑行道通向机坪的**度为 1 的末端节点**；`8 RAMP-A`、`TB`、`VA` 这类就是这条分支落下来的。
  - `R13R/31L` 这种"以跑道为边界"的写法，走跑道穿越段在 `apt.dat` 里的边来完成定位。
- 失败原因分三种写进日志：`滑行网络里无此滑行道` / `边界要素不在网络` / `两边界无连通路径`。

### 步骤 5｜落段 L2：FAA AM 面片兜底（`pick_am_polys`）

L1 失败的（典型是 `A4`、`A12`、`A14`、`A15` 这些编号分支，`apt.dat` 里根本没有这个边名）转到这里：

1. **取基面**：`am["B"]` 拿到 B 的所有面片（按路口切碎的很多块）。
2. **找交叉片**：通告写 `BTN A14 AND A15`，就在 `am` 里找 `B_A14`、`B_A15` 这种命名交叉片；名字形式不一致时用前缀匹配 + 后缀比对兜底。
3. **定锚点**：优先用交叉片面片的质心；缺一侧时退回"该要素自身面片"的质心，保证两个锚点都有。
4. **投影取区间**：以两个锚点连线为轴，把 B 的每一块面片质心投影到轴上得参数 `t`，保留 `-0.03 ≤ t ≤ 1.03` 且垂距 < **0.0016 度**（约 175 m）的面片——**这是"只画那一段"的核心**，否则会把整条 B 都涂红。最后并入两个交叉片。
5. **相邻兜底**：连锚点都缺时，取与两边界面片顶点距离 < 0.00035 度的基面。

实测效果：`TWY B BTN A14 AND A15` 从"只画出 1 个交叉片"提升到 **4 片、跨度约 290 m**，视觉上是一段连续红色带。同一 ETA 下 KJFK 的上图数量由 8 处提升到 10 处、未上图 0 条。

### 步骤 6｜落段 L3：仍未定位

进"未上图"清单（黄条），写明缺什么、为什么，**不猜、不硬凑位置**。这是刻意的保守设计：宁可留空也不画错位置，因为画错比不画更危险。

## 四、标注逻辑与视觉编码

### 底图怎么画（不是真航图，是矢量重绘）

- **坐标系**：以该机场全部滑行节点的纬度/经度均值为原点，做**本地等距平面近似**：`x = (lon - LON0) · cos(LAT0) · 111320`，`y = (lat - LAT0) · 110540`。单位米，`aspect="equal"`，所以图上距离可以直接量。
- **滑行道**：每条 `1202` 边画两遍——外层 5.2 pt `#ccd3db`、内层 2.6 pt `#e9eef3`，形成"浅色带 + 深色描边"的工程图质感。**只画边，不画面**，所以图面干净、不糊。
- **跑道**：用两端真实坐标 + `width_ft` 计算法向偏移生成矩形，深灰填充 `#39424c`、中线白色虚线、两端跑道端号（`04L`/`22R` 等）带描边效果保证压在深色上可读。
- **比例尺**：左下角画 **1 km** 标尺，按米制坐标真实长度绘制。
- **画幅**：16:9、170 dpi，左侧地图区占 68.5% 宽，右侧清单区占 27%。

### 关闭段怎么标

| 元素 | 编码 | 说明 |
|---|---|---|
| 关闭**线段** | 白色 9.5 pt 底 + 红色 `#e63946` 5.4 pt 主线，圆头端点 | 双层描边保证在任何底色上都能读 |
| 关闭**面片** | 红色填充 + 同色描边，**alpha 0.55** | 仅用于 AM 兜底的编号分支，视觉上与线段区分（面状 vs 线状） |
| 编号 | 红圆 `#b3202c` + 白字 | 与清单序号一一对应 |
| 引线 | 编号偏离目标时画细引线 | 指回真实位置，避免编号飘走失联 |
| 未定位 | 黄色方块 `#e0b23a` + 原因文字 | 明确"没画"而非"没关" |

### 编号避让（解决"编号压住滑行道字母/跑道号"）

按你选的方案 1 实现：先登记、再避让。

1. `PLACED` 列表记录已占用圆形区域，`reserve(x,y,r)` 登记、`clash(x,y,r)` 判冲突。
2. **先占跑道端号**（半径 95）与**所有滑行道字母**（半径 40，每个设计ator只在第一条边中点标一次，避免重复绘制）。
3. 编号从锚点出发，在 **16 个方向 × 5 个半径（150/215/285/365/455）** 的候选位里找第一个不冲突的位置；全冲突则取"最空"的位置并把引线拉细。

KJFK 中部 H/G/Z 密集区不再出现编号压字。

### 清单区（右侧）

每条三到四行：

1. **编号圈 + 名称 + 关闭**（`TWY B（A14–A15） 关闭`），右上角灰色 NOTAM 编号（`11/249`）。
2. **时间**：UTC，格式 `MM-DD HH:MMZ`；同一天只写一次日期（`11-20 04:00Z – 11:00Z`）；跨度 > 3 天带年份；超过 3 天在网页表格里标"长期"。
3. **灰色小字 = 通告原文**（清理后的 `E)` 正文），按 46 字符（拥挤时 76 字符）折行，最多 2 行，超出用 `…`。原文也上表，方便你直接对 FAA 原文，不用来回切窗口。
4. 条目 > 8 条自动进入 **tight 排版**：字号 8.6 / 6.7 / 6.2，行距压到 ≤ 0.054，原文折行放宽到 76 字符——这是 12 条不叠字的临界参数。

### 时间口径（你指定的两条）

- **所有时间一律 UTC**，输入框写"目标时间（UTC，航班预计到达）"，图上、表里、清单里不出现任何本地时。
- **目标时间 = 航班 ETA**，只保留与 `[ETA-6h, ETA+6h]` **区间有交集**的通告：`start <= ETA+6h and end >= ETA-6h`。不是"该时刻生效"——一条 04:00–11:00Z 的关闭，ETA 20:00Z 的航班根本碰不到，会被自然筛掉；而一条跨到次日 23:00Z 的长期关闭会保留。
- 起止时间解析失败的通告**默认保留**（宁可多标，不可漏标）。

### 图面文字

- 标题：`KJFK 机场关闭区域图`
- 副标题：`目标 ETA 2026-11-20 20:00Z，取 ±6 小时　·　通告 15 个关闭 → 上图 15 处，未定位 0 条`

## 五、精度与适用边界（必须知道的三条）

1. **这是示意图，不是航行图**。底图来自模拟飞行社区的场景数据（X-Plane），滑行道中心线位置与实测可能有数米级偏差；跑道位置来自 OurAirports（开源众包）。**不可用于运行决策、不可作为放行依据。**
2. **"哪一段"的精度取决于通告文本的清晰度**。通告写 `BTN A14 AND A15` 且两个边界在网络/面片里都存在时，截段可靠；通告只写 `TWY B CLSD` 而无区间时，只能整条标红；通告写的是已废弃或未录入的要素名时，只能进黄条。
3. **非美机场能力降级**。AM 面片仅覆盖美国及属地 221 个机场，其他国家机场的编号分支道（如 `A4`）会落进"未上图"；主干滑行道因为有 X-Plane 网络仍可正常标。若要补，需要自建"人工别名表"（把 `A4` 映射到某条边），这个机制目前**尚未实现**。

```
cache/<ICAO>.apt.dat        场景包解出的网络（KJFK 387 KB）
```

复现一条链路：

```bash
python airport_closure_app.py                 # 网页版，自动开浏览器
python airport_closure_app.py KJFK            # 命令行出图，全量通告
python make_chart_v2.py KJFK AT=2026-11-20T20:00   # 指定 ETA
```

几何不对 → 删 `cache/<ICAO>.apt.dat` 强制重下；解析不对 → 用 `re_parse.py`（纯正则）与 `parse_closures`（语义增强）对比差异。
