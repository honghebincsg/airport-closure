# 机场关闭通告上图工具 · 完整技术方案

版本 v1.0 ｜ 2026-11-20 ｜ 对应程序 `airport_closure_app.py` ｜ 样例机场 KJFK

本文是整个项目的主文档：数据从哪来、怎么算、怎么画、错在哪、下一步做什么。原有的《数据源与标注逻辑说明》《全球机场NOTAM公开源调研》《KLAX/PANC通告风险分析》作为分册保留，细节以本文为准。

---

## 一、问题定义

要解决的是航空情报里一个很具体的痛点：**通告文本说"某条滑行道关了，关在某两个要素之间"，但人脑很难把它翻译成"图上哪一小段"。**

一条典型通告：

```
TWY B BTN TWY A14 AND TWY A15 CLSD
```

翻译成图面语言是：在 B 这条滑行道上，A14 与 A15 两个交叉点之间的那一段涂红。难点有三个：

1. **文本到几何的映射**。通告只给要素名（B / A14 / A15），没有任何坐标，必须自己有拓扑数据才能截出区间。
2. **边界要素常常不在数据里**。A14、A15 这类编号分支道，在主流免费数据源里根本没有独立几何，只有一张张面片。
3. **排版**。几十个编号、上百个字母、跑道端号压在同一张图上，互相遮挡就会让图失去可用性。

**这个工具不做什么，比做什么更重要**：它是**示意图**，底图来自模拟飞行社区的场景数据，不是官方航图，**不可用于运行决策、不可作为放行依据**。图上页脚和几何基准行都印了这句话。

## 二、总体架构

```
                 ┌─────────────────────────────┐
                 │  FAA NOTAM Search（免密钥）   │
                 └──────────────┬──────────────┘
                                │ 全量分页拉取（curl_cffi 过 Akamai）
                                ▼
                     ┌────────────────────┐
                     │ 解析：文本 → 关闭对象  │  正则（确定性）
                     │  kind/name/b1/b2/时段 │  ＋可选 AI 兜底（P1 未实现）
                     └──────────┬─────────┘
                                │  对象列表
                                ▼
      ┌──────────────────────────────────────────────┐
      │ 落段三级（全部确定性几何计算）                    │
      │  L1  X-Plane apt.dat 网络 → 最短路径截出那一段    │
      │  L2  FAA AM_Taxiway 面片 → 投影取区间兜底        │
      │  L3  都失败 → 黄条"未上图"，写明原因，不猜         │
      └──────────────────────┬───────────────────────┘
                             │  带几何的关闭对象
                             ▼
                ┌──────────────────────────┐
                │ 渲染（matplotlib 矢量重绘）  │
                │  底图/关闭段/编号/字母/避让  │
                └──────────────┬───────────┘
                               ▼
                     PNG + 交互网页（本地 127.0.0.1）
```

**架构上的核心原则：几何与渲染 100% 确定性，AI 不参与。**

同样的通告 + 同样的缓存，跑一百次得到同一张图。这条原则是刻意选的——图上任何一个红段都对应可复算的坐标，出了问题能一步步回溯到源头，而不是"模型这次觉得标在这儿"。AI 只在文本语义层做辅助（且目前是离线核对，不在程序里）。

## 三、数据源全景

### 3.1 五个源，各管一段

| # | 层 | 来源 | 接口 | 覆盖 | 更新频率 | 实测新鲜度 |
|---|---|---|---|---|---|---|
| ① | 通告 | FAA NOTAM Search | `POST notams.aim.faa.gov/notamSearch/search` | 美国及属地 | 实时 | 抓取当刻（2026-11-20 18:35Z） |
| ② | 滑行网络 | X-Plane Scenery Gateway | `gateway.x-plane.com/apiv1/airport/<ICAO>` | 全球 | 不定期，作者上传 | KJFK 包 2025-04-15 批准 |
| ③ | 滑行道面 | FAA Airport Mapping | `services6.arcgis.com/.../AM_Taxiway/FeatureServer/0/query` | 美国及属地 **221 个机场** | 56 天周期 | 2025-08-07 → 2025-10-02 |
| ④ | 跑道 | OurAirports | `raw.githubusercontent.com/.../runways.csv` | 全球 | 每日 | 当天下载 |
| ⑤ | 官方航图 | FAA d-TPP AD | `aeronav.faa.gov/d-tpp/<cycle>/<图号>AD.PDF` | 美国 | 28 天周期 | cycle 2611（最新） |

四层职责必须分清，出问题时才定位得快：通告层知道"关了什么、关在哪两个要素之间、什么时段"；网络层提供拓扑用来截段；面层补编号分支道；参考层给跑道真实几何。

### 3.2 通告源：FAA NOTAM Search

```
POST https://notams.aim.faa.gov/notamSearch/search
Content-Type: application/x-www-form-urlencoded

searchType=0&designatorsForLocation=KJFK&offset=0&limit=50
```

免账号、免密钥。`offset` 递增到 `totalNotamCount` 取满。

**最大的坑是 TLS 指纹，不是 IP。** FAA 前置 Akamai 按 JA3/JA2 判机器人：同一台机器同一 IP，`requests` 返回 403，`curl_cffi(impersonate="chrome")` 返回 200。改 UA、加 Referer、带 Cookie 全部无效。这就是"换台电脑也 403"的真实原因。程序里装了 `curl_cffi` 自动用它，没装回退 `requests`（此时大概率 403，只能改用粘贴模式）。企业网还有一层 SSL 解密代理，会破坏 TLS 指纹，这种情况下只能走粘贴。

**正文取法**：`icaoMessage` 常返回整段报文（`Q)… A)… B)… C)… E)…`），必须正则取 `E)` 之后的部分，否则解析率大幅下降。尾部还有 `CLSDTWY ZRSTRCTN>` 这类粘连串要截断。

### 3.3 滑行网络：X-Plane `apt.dat`

两步换文件：

```
① https://gateway.x-plane.com/apiv1/airport/KJFK       → recommendedSceneryId（KJFK=106313）
② https://gateway.x-plane.com/scenery/download/106313  → zip 内 *.apt.dat（387 KB）
```

**为什么是它**：`apt.dat` 是 X-Plane 的地景文本规范，**带完整滑行道网络拓扑**（节点 + 边 + 边名）。全世界免费公开、能拿到"哪条边属于哪条滑行道"的数据基本只有它。OSM 有几何但拓扑和命名不可靠；FAA NASR 只有名字没有几何。

解析：`1201` 行 → 节点（纬度/经度/节点 ID，KJFK 1024 个）；`1202` 行 → 边（两个节点 ID + 边名，KJFK 731 条）。

**已知局限：`100` 行跑道定义经常不全（KJFK 只给 2 条），跑道几何绝不能用它。**

### 3.4 面层：FAA AM_Taxiway

```
GET https://services6.arcgis.com/ssFJjBXIUyZDrSYZ/arcgis/rest/services/AM_Taxiway/FeatureServer/0/query
    ?where=ICAO_ID='KJFK'&outFields=DESIGNATOR&returnGeometry=true
    &outSR=4326&geometryPrecision=6&f=geojson
```

免密钥公开 ArcGIS REST。每片一个 `Polygon`，`properties.DESIGNATOR` 是滑行道名。**关键价值：它把编号分支也命名了**——KJFK 有 `A4`、`A12`、`A14`、`A15`、`KD`，还有 `B_A15` 这种交叉片。这是 `apt.dat` 和 AD 图都给不了的东西。

KJFK 实测 452 片 / 230 个标识。覆盖美国及属地 221 个机场（本土 202、阿拉斯加 15、夏威夷 2、波多黎各 1、BAZ 1），**非美机场 0**（MMSM、MMUN、EGLL、ZSPD、RJTT 查询均空）。

坐标坑：GeoJSON 是 `[lon, lat]`，程序内部是 `xy(lat, lon)`，转换时极易写反。

### 3.5 跑道：OurAirports

`runways.csv` 全量约 3.8 MB，按 `airport_ident` 过滤。用 `le_ident`/`he_ident`、两端真实经纬度、`width_ft`（×0.3048 转米）。

**必须有它**：`apt.dat` 跑道只有 2 条，AD 图是 PDF 不好直接算，OurAirports 是唯一"免费 + 真实端点 + 带宽度"的表。

### 3.6 官方航图：FAA d-TPP AD（只做核验，不做底图）

`https://aeronav.faa.gov/d-tpp/2611/00610AD.PDF`（KJFK，cycle 2611，305 KB）

是矢量 PDF，`pdfplumber` 能抽曲线坐标，`pdftocairo -r 300` 能栅格化。

**但它没有成为主底图，原因三条：**

1. AD 图是**示意图纸**，有自己的比例与旋转（图内不严格正北），要跟经纬度对齐必须做相似变换配准；
2. 每张图的比例尺、图幅、旋转都不同，一个机场一套标定参数，无法批量；
3. 配准误差会直接叠加到关闭段的定位上，**反而降低准确性**——为了"看起来像官方图"而牺牲定位精度，是本末倒置。

实验脚本 `make_official_chart.py`（抽 PDF 黑填充长条当跑道 → 与 OurAirports 真实端点配对做 scale+rotation+translation → 把算出的关闭段反算回 PDF 坐标叠加）**未收敛，不是成品**。

> 关于 "AM 图 vs AD 图"：AM 是**地理要素数据库**（每片滑行道/跑道/机坪是带真实经纬度的矢量面，机器可读，用于 GIS 与机载地图）；AD 是**给人看的机场图**（含停机位编号、热区、标高、灯光等运行信息，视觉信息量远超 AM）。两者互补：AM 能算，AD 能看。工具选 AM 的几何、用 AD 做人工核验，正是这个分工。

### 3.7 编号体系：为什么图上只有 `11/295`，没有 `A0028/26`

实测 KJFK 全部 184 条通告的编号格式分布：**ICAO 系列格式（`A0028/26`）0 条**，美国国内格式（`11/295`）占绝大多数，另有 3 条 `LTA-N90-129` 类长期通告。

| | 美国国内体系 | ICAO 国际体系 |
|---|---|---|
| 编号形式 | `11/295`（月／当月流水） | `A0028/26`（系列字母＋序号／年份） |
| 报文前缀 | `!JFK 11/295` | `!KZNY A0028/26`（FIR 代码） |
| 依据 | FAA 国内 NOTAM 规程 | ICAO Annex 15 |
| 分发 | notamSearch 公开可查 | FAA 国际通告办公室（INO）经 AFTN |

试过给接口加 `notamType=INTL`、`international=true`，返回仍是那 184 条、仍是国内编号——**不是参数没调对，而是这个检索口只服务国内体系**。

三点必须说清：A 系列编号按**飞行情报区（FIR）**分配，不是按机场，`A0028/26` 属于某 FIR 当月第 28 号国际通告，可能同时涉及多个机场；两套编号**没有公开映射表**，同一内容在两个系统里编号互不相干，只能靠内容比对（时间＋地点＋正文）；中国用的就是 A 系列（空管局 AIS，走 AFTN，无公开 API）。

所以图上显示 `KJFK 11/295` 是对的：`KJFK` 是机场标识，`11/295` 是该机场体系内的通告号，FAA 通报表里就是这么写的，拿去核对不会对不上。

## 四、落段算法：从对象到那一段

### 4.1 L1：滑行网络精确截段（`solve`）

以 `TWY X` 为名取所有 `name == X` 的边构成子图 `sub`，再定两个端点：

- **边界节点集合** `bnodes(twy, bnd)`：先取"该滑行道节点集 ∩ 边界要素节点集"（**共节点**最可靠）；无交集则退化为**距离兜底**——计算边界要素每条线段，取该滑行道节点中距边界线 ≤ **150 m** 的节点。
- **两端句柄**：两侧边界节点集各取一个，用 `networkx.shortest_path` 在子图上求最短路径，路径节点序列就是被关闭的那一段。
- **只有名称、无 `BTN`**：取该滑行道**最大连通分量**的两个度为 1 的端点，整条关闭。
- **边界含 `TERMINAL/RAMP/APRON`**（机坪侧）：以另一侧边界节点为起点，找该滑行道通向机坪的**度为 1 的末端节点**。
- **`R13R/31L` 这种以跑道为边界**：走跑道穿越段在 `apt.dat` 里的边完成定位。

失败原因分三类写进日志：`滑行网络里无此滑行道` / `边界要素不在网络` / `两边界无连通路径`。

### 4.2 L2：AM 面片兜底（`pick_am_polys`）

L1 失败的（典型就是 `A4`、`A12`、`A14`、`A15` 这些编号分支，`apt.dat` 里没有这个边名）转到这里：

1. **取基面**：`am["B"]` 拿到 B 的所有面片（按路口切碎的很多块）。
2. **找交叉片**：通告写 `BTN A14 AND A15`，在 `am` 里找 `B_A14`、`B_A15` 这种命名交叉片；名字形式不一致时用前缀匹配 + 后缀比对兜底。
3. **定锚点**：优先用交叉片质心；缺一侧时退回"该要素自身面片"质心，保证两个锚点都有。
4. **投影取区间**：以两锚点连线为轴，把 B 的每块面片质心投影到轴上得参数 `t`，保留 `-0.03 ≤ t ≤ 1.03` 且垂距 < **0.0016 度（约 175 m）** 的面片，最后并入两个交叉片。**这是"只画那一段"的核心**，否则会把整条 B 都涂红。
5. **相邻兜底**：连锚点都缺时，取与两边界面片顶点距离 < **0.00035 度**的基面。

实测 `TWY B BTN A14 AND A15` 从"只画出 1 个交叉片"提升到 **4 片、跨度约 290 m**，视觉上是一段连续红带。

### 4.3 L3：仍未定位

进"未上图"清单（黄条），写明缺什么、为什么，**不猜、不硬凑位置**。这是刻意的保守设计：**画错比不画更危险**。

## 五、通告解析

纯正则，四步：

1. **截尾**（`clean`）：去掉 `RSTRCTN>` 之后的粘连串、`>` 残留、尾部 `MM/DD/YYYY HHMM`、`EST/EDT`、`CLSD` 之后的一切杂字。
2. **只留含 `CLSD`/`CLOSED` 的通告**，按 `,` `;` 拆并列片段。
3. **并列继承**：一条通告常写 `TWY B BTN A14 AND A15, TWY M BTN R13R/31L AND TWY A CLSD`——`CLSD` 只在最后一个片段。规则是：当前片段没 `CLSD`，但形如 `TWY X BTN …` 且**后面还有片段带 `CLSD`**，则继承关闭含义。
4. **边界对解析**：用 `PAIR` 正则把 `BTN <要素> AND <要素>` 拆成 `b1/b2`，要素允许带 `TWY`/`RWY`/`TERMINAL`/`RAMP`/`APRON` 前缀，允许 `13R/31L`、`RAMP-A` 写法。

输出对象：`{编号, 类型, 名称, 边界1, 边界2, 前缀类型, 起, 止, 是否继承, 命中证据, 原文}`。

**这套正则对 FAA 通告够用**，因为它是高度模板化的英文，句式就那几种。扩到欧洲 AIXM 或中文通告会吃力——所以有了第十一节的 P1。

## 六、时间口径

两条硬约定：

- **所有时间一律 UTC**。输入框写"目标时间（UTC，航班预计到达）"，图上、表里、清单里不出现任何本地时。页面里所有时间戳都是 UTC。
- **目标时间 = 航班 ETA**，只保留与 `[ETA-6h, ETA+6h]` **区间有交集**的通告：`start <= ETA+6h and end >= ETA-6h`。

注意这是"区间有交集"，不是"该时刻生效"。一条 `04:00–11:00Z` 的关闭，ETA 20:00Z 的航班碰不到，会被自然筛掉；而一条跨到次日 23:00Z 的长期关闭会保留。这才是运控真正关心的"这趟航班会不会受影响"。

起止时间解析失败的通告**默认保留**（宁可多标，不可漏标）。

## 七、渲染规范

### 7.1 底图（矢量重绘，不是贴图）

- **坐标系**：以机场全部滑行节点经纬度均值为原点做本地等距平面近似：
  `x = (lon - LON0) · cos(LAT0) · 111320`，`y = (lat - LAT0) · 110540`，单位米，`aspect="equal"`，图上距离可直接量。
- **滑行道**：每条边画两遍——外层 5.2 pt `#ccd3db`、内层 2.6 pt `#e9eef3`，形成"浅色带 + 深色描边"的工程图质感。**只画边不画面**，图面干净。
- **跑道**：两端真实坐标 + `width_ft` 算法向偏移生成矩形，深灰填充 `#39424c`、白色中线虚线、两端跑道端号带描边保证压在深色上可读。
- **比例尺**：左下角 1 km 标尺，按米制真实长度绘制。
- **画幅**：16:9，`figsize=(16,9), dpi=170` → 输出 2720×1530；左侧地图区约 68.5% 宽，右侧清单区 27%。

### 7.2 视觉编码

| 元素 | 编码 | 说明 |
|---|---|---|
| 关闭**线段** | 白 9.5 pt 底 + `#e63946` 5.4 pt 主线，圆头 | 双层描边，任何底色都能读 |
| 关闭**面片** | `#e63946` 填充 alpha **0.42** + 同色描边 | 仅用于 AM 兜底，面状 vs 线状一眼区分 |
| 编号（线段型） | 圆 `#b3202c` + 白字，R=108 | 与清单序号一一对应 |
| 编号（面片型） | 圆 `#dd5158`（**淡红**）+ 白字 | **编号颜色跟随关闭几何的颜色**，不是单纯按序号 |
| 主滑行道字母 | `#3f4a56` 深灰，6.5 pt（长名 5.8） | 网络边中点 |
| 分支道 / 边界要素 | `#b0525b` 淡红，5.5 pt 斜体 | `A4`/`A14`/`A15`/`KD` 这类，来自 AM 面片 |
| **跑道关闭时段** | 白底 + 淡红边框胶囊，`#b3202c` 字 7.2 pt | 贴在跑道法向外侧（偏移 = 跑道半宽 + 62 m），两侧各试一次取不冲突的一侧；**必须完全离开红带**，否则小字压在同一块深红上读不出 |
| 未定位 | 黄条 `#e0b23a` + 原因文字 | 明确"没画"而非"没关" |
| 引线 | 编号偏离目标时细引线 | 指回真实位置 |

**几何基准行**（图面第三行小字，`#8994a1` 8.6 pt）：

```
几何基准 · 滑行网络 2025-04（X-Plane 场景包） ｜ 滑行道面 0901Z 07 Aug 2025 – 0901Z 02 Oct 2025（FAA AM）　·　非当日数据，仅作示意
```

两套底图数据的版本日期直接印在图上，避免被误读为"今天的状态"。日期来自两个缓存：`apt_meta`（场景包的 `dateApproved`）与 `am_meta`（AM 服务 description 自述的生效期，缓存 7 天）。

### 7.3 清单区（右侧）

每条三到四行：

1. **编号圈 + 名称 + 关闭**（`TWY B（A14–A15） 关闭`），右上角灰色通告编号 `KJFK 11/249`（**不带感叹号**，`!` 是通报表前缀，图上不需要）。
2. **时间**：UTC，`MM-DD HH:MMZ`；同一天只写一次日期（`11-20 04:00Z – 11:00Z`）；跨度 > 3 天带年份；超过 3 天网页表格标"长期"。
3. **灰色小字 = 通告原文**（清理后的 `E)` 正文），按 46 字符（拥挤时 76）折行，最多 2 行，超出 `…`。
4. 条目 > 8 条自动进 **tight 排版**：字号 8.6 / 6.7 / 6.2，行距压到 ≤ 0.054，原文折行放宽到 76 字符——这是 12 条不叠字的临界参数。

### 7.4 标题、声明与页脚

```
KJFK 机场关闭区域图                             [此图只作参考，不作为飞行或放行依据]
目标 ETA 2026-11-20 20:00Z，取 ±6 小时　·　通告 9 个关闭 → 上图 9 处，未定位 0 条
几何基准 · 滑行网络 2025-04（X-Plane 场景包） ｜ 滑行道面 2025-08~10（FAA AM）
```

**免责声明出现三次，措辞固定**，因为这是示意图，误用的代价很大：

1. **标题行右侧的醒目红框**——白底 `#b3202c` 粗体 11.5 pt、1.5 pt 红边圆角框，与标题同一水平线靠右。放在标题行而不是图内，是因为图内任何位置都可能压到道面，而标题行右侧永远是空白区。
2. **页脚**——数据来源 + `非官方航图，此图只作参考，不作为飞行或放行依据`。
3. **标题区"非当日数据，仅作示意"**（几何基准行的尾缀）。

页脚完整文案：

```
数据：FAA NOTAM Search · X-Plane 滑行网络 · FAA AM 滑行道面 · OurAirports 跑道　|　非官方航图，此图只作参考，不作为飞行或放行依据
```

## 八、排版避让（三层机制）

这张图的文字密度很高：13 个编号、100 多个滑行道字母、十几个跑道端号，还有 `CLSD 04R/22L` 这种长标签。三层机制保证互不遮挡：

**第一层：先占位。** `PLACED` 列表记录已占用圆形区域，`reserve(x,y,r)` 登记、`clash(x,y,r)` 判冲突。先占**跑道端号**（r=95）和 **`CLSD xxx` 长标签**（r=172），它们位置固定不可动。

**第二层：编号避让。** 编号从锚点出发，在 **16 个方向 × 7 个半径（150/210/280/360/450/560/680）** 的候选位里找第一个不冲突的位置；全冲突则取"最空"位置并把引线拉细，再不行退到**整幅网格搜索**兜底。

**第三层：字母最后画。** 滑行道字母的候选位是：原点 + 法向 ±72/132/200/270 + 5 圈（85/145/215/295/380）× 8 方向，共 **49 个**，按距离排序逐个试 `clash`，通过才落笔；冲突时沿法向平移；实在挤不下就不标（宁缺不压）。

**字母标全策略**：从"每个单字母只标一次"改为**按（名字 + 连通分量）逐组标注**，取该组最长边的中点，边长 < 50 m 的残段跳过。KJFK 从 26 个字母涨到 100 多个。加上 AM 面片型、边界要素型两类，实际落位失败数为 0。

## 九、运行与交付形态

**单文件** `airport_closure_app.py`：标准库 `http.server` + 内嵌单页 UI，启动自动开浏览器 `127.0.0.1:8765`。三种用法：

```bash
python airport_closure_app.py                       # 网页版，浏览器里填机场+ETA
python airport_closure_app.py KJFK                  # 命令行出图，全量通告
python make_chart_v2.py KJFK AT=2026-11-20T20:00    # 指定 ETA
```

依赖：`requests`、`networkx`、`matplotlib`（可选 `curl_cffi`，装了才能直连 FAA）。

**壳方案的取舍已经定了：维持浏览器方式。** Go 编译壳（把 Python 塞进二进制）、pywebview 原生窗口、全 Go 重写都评估过并否掉——单文件 Python + 本地网页已经做到"零安装、改一行立刻生效"，套壳只会让升级和排错变难。

缓存：

```
cache/<ICAO>.apt.dat         场景包解出的网络（KJFK 387 KB）
cache/<ICAO>.am_taxiway.json FAA AM 面片（KJFK 452 片，258 KB）
cache/<ICAO>.apt_meta.json   场景包批准日期（几何基准行用）
cache/am_meta.json           AM 服务生效期（缓存 7 天）
cache/runways.csv            跑道表副本
data/kjfk_notam_raw.json     通告快照（离线复现）
```

排错路径：几何不对 → 删 `cache/<ICAO>.apt.dat` 强制重下；解析不对 → `re_parse.py`（纯正则）与 `parse_closures` 对比差异；排版不对 → `CHART_DEBUG=1` 跑，读 `/tmp/chart_badges.json`（含 badges、labels 落位成功标志、xlim/ylim、axes 位置、dpi）。

## 十、精度边界与已知缺陷

1. **这是示意图，不是航行图。** 底图来自 X-Plane 场景（2025-04）、AM 面片（2025-08~10）、OurAirports 众包数据。滑行道中心线与实测可能差数米，跑道位置来自开源众包。**不可用于运行决策。**
2. **"哪一段"的精度取决于通告文本清晰度。** 写 `BTN A14 AND A15` 且两端在数据里都有 → 截段可靠；只写 `TWY B CLSD` 无区间 → 只能整条标红；写已废弃或未录入的要素 → 进黄条。
3. **非美机场能力降级。** AM 面片只覆盖美国及属地 221 个机场，其他国家的编号分支道（`A4` 这类）会进"未上图"；主干滑行道因有 X-Plane 网络仍可标。补法是自建别名表，**尚未实现**。
4. **数据新鲜度不可能追上实时。** 通告是实时的，几何不是——几何基准行就是为这件事印上去的。如果机场刚完成道面改造（新滑行道启用、旧道拆除），图上可能是旧形态，此时关闭段落位会偏。**通告权威性高于几何，冲突时以通告为准，图只作参考。**

## 十一、下一步计划

### P1（近期，已确定要做）AI 解析兜底

**现状**：解析 100% 正则，程序内零 AI、零 API key、零大模型 SDK（全文件搜 `openai/anthropic/api_key/chat/completions` 零命中）。`ai_parse.json` 是会话中人工/AI 核对的对照样本，**程序不读它**（`ai_parse` 在代码里零命中）。

**目标**：在不破坏确定性的前提下，把正则覆盖不住的表达接住。

**触发条件（只在必要时调用，控制成本）**：

- 原文含 `CLSD`/`CLOSED`，但正则未产出任何对象 → 调 AI
- 正则产出了对象，但 `b1`/`b2` 缺失且原文含 `BTN`/`BETWEEN`/`SEGMENT` → 调 AI 补边界
- 其余情况**一律不调 AI**

**输出契约（schema 与正则完全对齐）**：

```json
{"kind":"TWY","name":"R","b1_type":"TWY","b1":"H","b2_type":"TWY","b2":"G","status":"CLSD","confidence":0.9}
```

字段名、枚举值必须与 `parse_closures` 输出一致，AI 只填内容，不改结构。

**对撞规则（沿用已验证的三条）**：

| 情形 | 处理 |
|---|---|
| 正则命中、AI 未命中 | 以正则为准 |
| AI 命中、正则未命中 | 进"待复核"清单，图上照画但编号加虚线框标记 |
| 两边都未命中、原文含 `CLSD` | 报警，进黄条 |
| 两边都命中但边界不同 | 以正则为准，差异写入差异报告供人工抽查 |

**工程约束**：

- 默认关闭。配置里不填 key 就永远走纯正则，行为与现在完全一致。
- 填了 key 才启用，key 存本地配置文件，**不写进代码、不写进日志**。
- 接口用 OpenAI 兼容格式（火山方舟 Ark `/api/v3/chat/completions`、DeepSeek 均可），`temperature=0`，请求超时 20 s，失败即降级为正则结果，**绝不让 AI 失败阻塞出图**。
- 每次运行把"AI 调用次数 / 命中数 / 与正则差异"写进日志尾部，便于评估是否值得保留。
- **前提风险**：企业网 SSL 解密代理会破坏 TLS 指纹，FAA 已验证 403，大模型 API 走同一链路大概率也被拦。所以这个能力实际是"在能联网的机器上补漏"，不能作为生产主路径。

**验收**：拿 KJFK 现有 184 条做回归，AI 兜底不得改变已有的 13 个对象（一个都不能动）；然后构造 20 条欧洲/中文风格通告测试集，看命中率。

### P2 非美机场编号分支别名表

AM 面片只覆盖美国。非美机场（如墨西哥 MMSM、欧洲各大机场）遇到 `A4`、`A15` 这类编号分支时会落进黄条。做法：人工/半自动把编号名映射到 X-Plane 网络里的某条边或某个节点区间，存成 `alias/<ICAO>.json`。覆盖面靠人工积累，先做几个高频机场试点。

### P3 官方航图配准（可选，价值低于 P1/P2）

把 d-TPP AD 的矢量 PDF 与经纬度做相似变换配准，让底图"看起来像官方图"。前面分析过：每机场一套标定参数、配准误差会叠加到定位精度上，**投入产出比低**，除非有明确的可视化合规需求，否则不做。

### P4 多时段时间轴

同一机场把一天内所有关闭按时间轴排开，看"什么时段哪些道不能用"。已有雏形 `make_timeline.py`，未产品化。

### P5 批量与自动化

一个机场列表批量出图（如南航所有通航点），输出到一个目录 + 汇总表。可用于每日运行前自动生成"今日受影响机场图"。
